# Library Documentation Style Guide

## 文体

- 日本語は簡潔な常体で書く．
- 句読点は `，` と `．` を用いる．
- 「できる」「求める」「処理する」「表す」「呼ぶ」などの短い説明を好む．
- 読者は競技プログラミング，C++，基本的なデータ構造・代数・数式記法に慣れている前提にする．
- 導入文は長くしない．背景説明よりも，何を計算するか，どの操作ができるか，計算量はいくらかを優先する．
- 原則として太字，斜体，callout などの強調は使わない．注意点は短い文として書く．

## 冒頭の形

対象に合う場合は以下の形を使う．

```markdown
<問題名>を解く．

<アルゴリズム名> により $O(...)$ 時間．
```

```markdown
列 $A=(A_0,A_1,\dots,A_{N-1})$ があり，はじめ全て $0$．

以下のクエリを，空間計算量 $\Theta(N)$ のもとクエリあたり時間計算量 $O(\log N)$ で処理する．
```

```markdown
モノイド $(T,\cdot,e)$ を考える．

長さ $N$ の列 $A=(A_0,A_1,\dots,A_{N-1})$ に対し，以下の操作を行える．
```

## 見出し

- 短いページに不要な top-level heading は置かない．
- `#` は近い docs が使っている場合や，独立した名前付きページの場合だけ使う．
- `##` は以下を優先する：
  - `## 使い方`
  - `## アルゴリズム`
  - `## 仕組み`
  - `## 計算量`
  - `## 実装`
  - `## 資料`
  - `## 参考資料`
- `###` は `### add`, `### sum`, `### push` のような操作やアルゴリズムの段階に使う．
- 見出しは短くする．英語のアルゴリズム名はそのままでよい．

## API 箇条書き

メソッドは inline code，日本語のコロン，必要なら計算量を添えて説明する．

```markdown
- `set(p, x)`：$A_p \gets x$ とする．$O(\log N)$ 時間．
- `prod(l, r)`：$A_l\cdot A_{l+1}\cdot\cdots\cdot A_{r-1}$ を取得する．$O(\log N)$ 時間．
- `lower_bound(f)`：$f(A_0+A_1+\cdots+A_{p-1})$ が真となる最小の $p$ を求める．
```

指針：

- メソッド名と引数は backtick で囲む．
- code span の後に `：` を置く．
- 代入に近い操作は `$A_p \gets x$` のように書く．
- 注意点は原則として通常の文で書く．既存 docs に合わせる場合だけ太字を許容する．
- 定義や二分探索の派生ではネストした箇条書きを使ってよいが，深くしない．

## 数式

- 計算量は `$O(...)$`, `$\Theta(...)$`, `$\tilde O(...)$` のように書く．
- 不等号は `$0\leq l\leq r\leq N$`, `$\lt`, `$\gt`, `$\leq`, `$\geq` を一貫して使う．
- 列は `$A=(A_0,A_1,\dots,A_{N-1})$` のように `\dots` を使う．
- 導出には display math を使い，長い式変形では `align*` を使う．
- 局所的な記号は使う直前に定義する．

## アルゴリズムと証明

- 中心となる漸化式，不変量，変形を先に示す．
- 既存 docs の粒度なら自明な証明は省略してよい．例：`証明は省略．`
- 詳細な仕組みは長い文章よりも，短い段落と数式で説明する．
- 標準的なアルゴリズムの概略には pseudocode の code fence を使ってよい．識別子は説明と近い単純なものにする．

## 参考資料

末尾に `## 資料` または `## 参考資料` を置く．箇条書きには論文，書籍，記事，実装への参照を置いてよい．

```markdown
## 資料

- Author. Title. URL
- [記事タイトル](https://example.com)
```

## 避けること

- 対象 doc がその粒度でない限り，初心者向けチュートリアルにしない．
- 周辺 docs が使っていない限り，大きな例や sample I/O を追加しない．
- 簡潔な既存記法を冗長な文章に置き換えない．
- docs の句点に `。` を使わない．
- 周辺で使われていない限り，太字，表，callout，絵文字のような装飾的 Markdown を導入しない．
